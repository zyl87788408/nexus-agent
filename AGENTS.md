# AGENTS.md: working notes for /opt/nexus-agent

## Non-negotiable product rule

**Never report work that was not done.** A task reaches `completed` only when every step
produced non-empty verified output. Any response generated by the fallback backend must be
labelled `simulated: true`. Never "fix" a test by relaxing this invariant.

`nexus/core/execution_loop.py::_classify_step` is the single gate enforcing it.

## Hard invariant: offline means offline

All outbound network access must go through `nexus/net.py` (`NetworkPolicy.check`). Do not
call `urllib`, `requests`, `socket`, or `http.client` directly anywhere else. In `offline`
mode any non-loopback target must raise `CloudBlockedError` **before** a socket opens.

Verify with the socket-level spy in `tests/test_runtime_integration.py`, or:

```bash
unshare -n .venv/bin/python -m unittest discover -s tests -t .
```

## Commands

```bash
.venv/bin/python -m unittest discover -s tests -t . -v   # full suite (198 tests, ~3s)
.venv/bin/python server.py                               # port 8085, loopback only
```

Run the full suite before committing. It is fast; there is no excuse to skip it.

## Architecture map

* `nexus/config.py`: `Config` + `Mode`. Config file is `0600`; secrets are stored as env
  var **names**, never values. Corrupt config falls back to defaults instead of raising.
* `nexus/net.py`: the only egress point.
* `nexus/core/runtime.py`: wires every subsystem (`NexusRuntime`). `chat()` returns
  `(text, model)`; use `chat_detail()` for `(text, model, source)`.
* `nexus/core/execution_loop.py`: plan, execute, verify, retry, resume.
* `nexus/core/journal.py`: append-only journal + atomic checkpoints.
* `nexus/models/selector.py`: filter by fit, rank by size (largest first), lazy probe.
* `nexus/tools/sandbox.py`: path jail; shell off by default.
* `nexus/adapters/`: plugin loader, manager, permissions, context.

## Security invariants that are easy to break

These were each violated at some point and fixed; keep them fixed.

* **Capability access goes through the permission gate.** `PluginContext.services` is a
  `GatedServices` mapping, not the host dict. Reading `services["tools"|"memory"|
  "model"|"filesystem"]` requires the matching manifest permission and raises
  `PermissionError` otherwise; assignment raises `TypeError`. Never hand a plugin the raw
  host mapping again.
* **A plugin that fails to start must leave nothing behind.** `setup()` can register
  tools and then raise. `PluginManager.activate()` snapshots the tool registry and
  unregisters whatever the failed plugin added; do not treat "not in `modules`" as
  enough to mean "not active".
* **Rejected manifests are reported, not dropped.** Discovery returns skip reasons keyed
  by directory; duplicate plugin names are rejects too. Silent absence made a typo look
  like an empty plugin directory.
* **Plugins are trusted in-process code.** The loader gives each plugin its own module
  name to avoid import collisions and contains failures; it is not a sandbox. Do not
  describe it as one.
* **OFFLINE means no egress, and that is enforced in one place.** Model/API traffic goes
  through `nexus/net.py`. `tools.allow_shell` is a second path (curl/git/python), so
  combining it with OFFLINE mode is a startup `ValueError`. Filtering shell commands for
  network use was rejected as unreliable; do not replace the refusal with a filter.
* **Evidence, not output.** A step only counts as completed when its output is verified
  and is not merely an echo of its own instruction.
* **No fabricated hardware or results.** `gpu: None` when there is no GPU; fallback
  output is labelled `simulated: true`.

## Testing conventions

* Prefer real code paths. `tests/helpers.py::EchoBackend` is a genuine `ModelBackend`,
  not a mock of the engine; use it instead of patching internals.
* Do not let tests hit the real network. Patch `socket.socket.connect` to raise instead
  of relying on timeouts; a real timeout test took 60s before this was fixed.
* When a test encodes old false-success behaviour, rewrite the assertion and explain why
  in a docstring. Do not weaken the invariant to make a test pass.
