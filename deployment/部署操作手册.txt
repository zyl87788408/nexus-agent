================================================================
NEXUS 引擎 - 远程部署操作手册（内部人员用，勿发给客户）
================================================================
适用版本：NEXUS 2.0.0
手册版本：v1.0
更新日期：2026-11-07

本手册给"远程操作客户电脑"的实施人员使用。
每一步都写明：做什么、为什么、做错会怎样。
遇到手册没写的情况，停下来联系技术负责人，不要自己试。


================================================================
第 1 部分  开工前必须问清客户的 6 件事
================================================================

远程连上之前，先通过微信/电话确认这些。任何一项不确认，
都可能白干一小时。

--------------------------------------------------------------
1. 电脑是 Windows 还是 Mac？
--------------------------------------------------------------
   Windows  → 走 ① 环境检测.bat / ② 一键部署.bat / ③ 开机自启.bat
   Mac      → 走 Mac部署命令.txt（手动敲命令，没有 .bat）

   【重要】Mac 没有一键脚本，全程手敲命令，耗时约 20 分钟。
   Windows 约 10 分钟。

--------------------------------------------------------------
2. 内存多大？
--------------------------------------------------------------
   双击"此电脑"→右键→属性→"已安装内存(RAM)"

   4 GB        → 装不了，直接告诉客户需要升级（最低 8 GB）
   8 GB        → 能装，但只能跑 qwen2.5:3b（约 2 GB）
   16 GB       → 推荐，跑 qwen2.5:7b（约 5 GB）
   32 GB 以上  → 跑 qwen2.5:14b（约 9 GB）

   【为什么先问】8 GB 客户跑 7B 模型会卡到不能用，
   客户会认为"你们的软件很烂"。提前说清预期。

--------------------------------------------------------------
3. 磁盘 C 盘还剩多少？
--------------------------------------------------------------
   至少 10 GB。模型本身 2-9 GB，还要留空间给系统。

   不够就建议客户清理，或问能不能装到 D 盘
   （把整个文件夹放 D 盘，脚本会自动识别所在盘符）。

--------------------------------------------------------------
4. 电脑上装的是 32 位还是 64 位系统？
--------------------------------------------------------------
   "此电脑"→右键→属性→"系统类型"

   32 位 → 装不了。NEXUS 需要 64 位系统 + 64 位 Python。
   客户如果坚持，直接说明不支持，别硬装。

--------------------------------------------------------------
5. 装没装杀毒软件？360 / 腾讯电脑管家 / 火绒？
--------------------------------------------------------------
   这些软件会拦截 pip 安装，导致"依赖装不上"。

   【处理方式】部署全程请客户临时退出这些软件，
   或把 NEXUS 文件夹加入白名单。部署完再开回来。

--------------------------------------------------------------
6. 客户平时用什么客户端？
--------------------------------------------------------------
   Cherry Studio（最常见）/ Open WebUI / 其他

   部署完要教客户怎么连。手册第 6 部分有对应说明。

第 2 部分  远程连接与文件传输
================================================================

--------------------------------------------------------------
2.1 用什么远程工具
--------------------------------------------------------------
   推荐：向日葵 / ToDesk / 微信远程（最省事）

   【注意】不要用"远程桌面"（mstsc）装，
   Windows 家庭版不支持，客户可能连不上自己电脑。

--------------------------------------------------------------
2.2 文件怎么传
--------------------------------------------------------------
   把 NEXUS部署包.zip（58 KB）传给客户，步骤如下：

   1. 微信/QQ 直接发文件给客户
   2. 让客户保存到【桌面】
   3. 远程连上后，你来操作解压

   【关键】必须让客户"解压"，不能直接在压缩包里双击。
   解压方法：右键 zip → "全部解压缩" → 确定

   解压后桌面会出现"NEXUS引擎"文件夹。

--------------------------------------------------------------
2.3 解压后应该看到什么（核对这 5 个）
--------------------------------------------------------------
   NEXUS引擎/
   ├── ① 环境检测.bat
   ├── ② 一键部署.bat
   ├── ③ 开机自启.bat
   ├── nexus.pyz          52 KB
   ├── requirements.txt
   ├── 使用说明.txt
   └── Mac部署命令.txt

   少任何一个 → 压缩包没下完整，重新发一次。

   【验证方法】右键 nexus.pyz → 属性 → 看大小
   必须是 52 KB 左右（52,701 字节），明显偏小说明损坏。

第 3 部分  第一步：运行环境检测
================================================================

--------------------------------------------------------------
3.1 怎么运行
--------------------------------------------------------------
   双击"① 环境检测.bat"

   【可能遇到】Windows 提示"已保护你的电脑"
   → 点"更多信息"→"仍要运行"

   【可能遇到】蓝底白字一闪就没了
   → 说明脚本崩溃了，截图发给技术负责人

--------------------------------------------------------------
3.2 看懂检测结果
--------------------------------------------------------------
   脚本跑完后会给出明确结论，只有两种：

   ┌──────────────────────────────────────────┐
   │  结果：可以安装                            │
   │  下一步：双击"② 一键部署.bat"开始安装。     │
   └──────────────────────────────────────────┘

   ┌──────────────────────────────────────────┐
   │  结果：不能直接安装，需先解决以下问题        │
   │  --------------------------------------------------
   │  [阻塞] 具体原因...                        │
   └──────────────────────────────────────────┘

--------------------------------------------------------------
3.3 "不能安装"的 7 种原因，怎么处理
--------------------------------------------------------------

【阻塞 1】操作系统版本或位数不满足
   → 需要 64 位 Win10 1803+。Win7/Win8/32 位系统都不行。
   → 告诉客户必须换电脑或升级系统。装不了就是装不了。

【阻塞 2】Python 未安装 / 版本低于 3.10 / 是 32 位
   → 让客户装 Python 3.10 或更高（推荐 3.12）
   → 下载：https://www.python.org/downloads/
   → 【最容易犯的错】安装时忘记勾选
      "Add Python to PATH"，勾选框在安装界面最下面。
      不勾的话脚本找不到 Python，白装。
   → 装完要重新打开命令行，PATH 才生效

【阻塞 3】pip 不可用
   → 让客户在命令行执行：python -m ensurepip --upgrade
   → 还不行说明 Python 装坏了，卸载重装

【阻塞 4】内存不足 8 GB
   → 装不了。建议客户升级内存或换套餐。

【阻塞 5】磁盘剩余不足 10 GB
   → 让客户清理磁盘。可以用 Windows 自带"磁盘清理"。
   → 或把文件夹挪到空间大的盘（D 盘等）

【阻塞 6】网络不通或缺少 curl
   → 检查客户能不能上网（打开浏览器试试）
   → 公司网络可能挡了 pypi，让客户用手机热点试
   → "缺少 curl"：Win10 1803+ 自带，老系统会缺

【阻塞 7】程序文件缺失
   → 重新解压压缩包，确认 nexus.pyz 在文件夹里

--------------------------------------------------------------
3.4 "注意"类提示怎么处理（不阻塞，但要看）
--------------------------------------------------------------

   [注意] 内存偏小         → 只能装小模型，提前跟客户说清
   [注意] 无法访问 ollama.com → 模型下不了，需手动拷贝（见 5.4）
   [注意] 非管理员权限      → 可能失败，见 4.3
   [注意] 有安全软件        → 提前退出杀毒软件
   [注意] 有端口被占用      → 部署脚本会自动处理，不用管

--------------------------------------------------------------
3.5 【必须做】截图存档
--------------------------------------------------------------
   检测结果窗口不要急着关。
   截图，存到"客户名_检测结果.png"，发给技术负责人备份。

   【为什么】出问题时能证明部署前环境是什么状态。


================================================================
第 4 部分  第二步：一键部署
================================================================

--------------------------------------------------------------
4.1 怎么运行
--------------------------------------------------------------
   双击"② 一键部署.bat"

   脚本会自动做 6 件事，全程约 3-8 分钟（含下模型）：
   [1/6] 检查 Python
   [2/6] 清理占用端口
   [3/6] 安装依赖（fastapi/uvicorn/pydantic）
   [4/6] 后台启动 NEXUS 服务
   [5/6] 健康检查
   [6/6] 安装模型（会问你）

   【注意】第 3 步装依赖时窗口看起来像卡住，是正常的。
   清华镜像源下载，通常 30 秒 - 2 分钟。别关窗口。

--------------------------------------------------------------
4.2 第 6 步会问你一句
--------------------------------------------------------------
   窗口会显示：

      本机内存：16 GB
      推荐模型：qwen2.5:7b  (约 5 GB)

      下载需要联网一次，之后即可完全离线运行。

      是否现在下载该模型？[Y/N]:

   → 选 Y：自动下载，带进度条，约 2-10 分钟看网速
   → 选 N：跳过，服务照样能用，但回答是兜底的假文字

   【必须选 Y】除非客户明确说"我自己装模型"。
   选了 N，客户问问题得到的是固定套路回复，
   客户会认为产品是假的。这是最容易出事的地方。

   【如果要跳过】事后补救：
   在命令行敲：ollama pull qwen2.5:7b
   不用重装 NEXUS，装完直接生效，不用重启。

--------------------------------------------------------------
4.3 部署失败怎么办
--------------------------------------------------------------

失败时窗口会显示"部署失败"并列出原因。按下面排查：

【情况 1】依赖安装失败
   → 90% 是网络问题或杀毒软件
   → 先确认网络能开网页
   → 退出 360/腾讯管家/火绒，重跑脚本
   → 还不行换手机热点

【情况 2】"端口 8085 被占用"且清理失败
   → 说明当前不是管理员权限
   → 关掉窗口，右键脚本 → "以管理员身份运行"

【情况 3】健康检查一直失败
   → 打开任务栏，找"标题为 NEXUS Server 的最小化窗口"
   → 那个窗口里有真正的报错信息
   → 截图发技术负责人

【情况 4】Python 报"不是内部或外部命令"
   → Python 没加进 PATH
   → 卸载 Python 重装，安装时勾选 "Add Python to PATH"

--------------------------------------------------------------
4.4 【必须做】部署成功后的确认
--------------------------------------------------------------
   窗口显示"部署成功"后，做这 3 个确认：

   1. 打开浏览器，访问：http://127.0.0.1:8085/health
      应该看到：{"status":"ok","service":"nexus-agent",...}

   2. 访问：http://127.0.0.1:8085/v1/models
      应该看到模型列表，里面有 qwen2.5:xxx
      如果只有 "nexus-local"，说明模型没装好

   3. 任务栏应该有"标题为 NEXUS Server 的最小化窗口"
      这个窗口不能关！关了服务就停了。

   【重要】第 3 点要跟客户强调：
   那个最小化的黑窗口是正常的，不是病毒，不能关。

   【自动完成】② 脚本结束前会自动调用 ③ 开机自启.bat /quiet，
   设置开机自启。设置好后：
     · 开机自启，无需再点任何东西
     · 运行时无窗口（VBS 隐藏启动），任务管理器里是 python.exe
   如需确认是否已设置，看这个文件是否存在：
     %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\NEXUS自启.vbs


================================================================
第 4.5 部分  开机自启（② 会自动设置，这里是备用知识）
================================================================

--------------------------------------------------------------
4.5.1 它是怎么实现的
--------------------------------------------------------------
   ③ 开机自启.bat 会在系统的"启动文件夹"里放一个 VBS 脚本：

     %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\NEXUS自启.vbs

   开机时 Windows 自动运行这个 VBS，VBS 再以"隐藏窗口"方式
   启动 nexus.pyz。所以客户看不到任何窗口，但服务已经在跑。

   【为什么不用 pythonw】
   pythonw 没有标准输出，uvicorn 写日志时会抛异常。
   用 python + 隐藏窗口（VBS 的窗口样式 0）更稳，
   两者都能正常隐藏。

   【为什么不用任务计划程序】
   任务计划程序的 XML 配置在部分精简系统/安全软件下会被拦，
   启动文件夹更简单、更好排查，出问题删一个文件就解决。

--------------------------------------------------------------
4.5.2 三种使用方式
--------------------------------------------------------------

  自动（正常情况）
    ② 一键部署.bat 成功后自动调用 ③ /quiet，无需人工操作

  手动开启/取消
    双击 ③ 开机自启.bat
    · 未启用 → 直接设置
    · 已启用 → 问"是否取消"，选 Y 删除

  检查是否已启用
    按 Win+R，输入：  shell:startup
    看文件夹里有没有 NEXUS自启.vbs

--------------------------------------------------------------
4.5.3 四个必须注意的点
--------------------------------------------------------------

  ① 文件夹不能移动
     VBS 里写的是绝对路径。客户如果把"NEXUS引擎"文件夹
     挪到别处（比如从桌面挪到 D 盘），自启会失效。
     → 移动后必须重新双击 ③

  ② 服务运行时没有窗口
     客户可能会说"我没看到它运行"。
     验证方法：浏览器访问 http://127.0.0.1:8085/health
     或任务管理器里看有没有 python.exe

  ③ 要关闭服务
     任务管理器 → 详细信息 → 找 python.exe → 结束任务
     （注意：可能有多个 python.exe，认准内存占用较大的那个）

  ④ 安全软件可能删掉启动项
     360/火绒等有时会把"启动文件夹里的 VBS"当可疑项处理。
     如果客户反馈"重启后不能用了"，先查这个文件还在不在。

--------------------------------------------------------------
4.5.4 端口冲突（重要）
--------------------------------------------------------------
   自启服务占用 8085。如果之后再双击 ② 一键部署.bat，
   它会先清理占用端口的进程，也就是把自启的那份停掉，
   再重新启动一份。这不会破坏自启设置，属正常。

   【但要注意】② 部署脚本本身不会自己开机启动，
   真正一直生效的是 ③ 写的那个 VBS。


================================================================
第 5 部分  模型安装（如果第 4 步选了 N）
================================================================

--------------------------------------------------------------
5.1 先检查 Ollama 装没装
--------------------------------------------------------------
   打开命令行（Win+R → 输入 cmd → 回车），执行：
       ollama list

   有输出 → 已装，跳到 5.3
   报"不是内部或外部命令" → 没装，看 5.2

--------------------------------------------------------------
5.2 装 Ollama
--------------------------------------------------------------
   1. 打开 https://ollama.com/download/windows
   2. 下载 OllamaSetup.exe，双击安装（一路下一步）
   3. 装完它会自动在后台运行（任务栏有个羊驼图标）
   4. 关掉命令行，重新打开一个（PATH 才生效）
   5. 执行 ollama list 验证

   【注意】Ollama 默认装在 C:\Users\用户名\AppData\Local\Programs\Ollama
   不在 PATH 里也可能能用（部署脚本会自动补路径）

--------------------------------------------------------------
5.3 下载模型
--------------------------------------------------------------
   在命令行执行（按内存选一个）：

   8 GB   →  ollama pull qwen2.5:3b
   16 GB  →  ollama pull qwen2.5:7b
   32 GB+ →  ollama pull qwen2.5:14b

   【注意】进度条走完才是真装好。中断了要重新执行。
   【注意】下载量 2-9 GB，客户如果是流量套餐要提前问。

   装完验证：
       ollama list
   应该看到刚装的模型。

   再验证 NEXUS 认不认：
       浏览器访问 http://127.0.0.1:8085/v1/models
   应该能看到这个模型（不需要重启 NEXUS）。

--------------------------------------------------------------
5.4 客户完全没网，怎么离线装模型
--------------------------------------------------------------
   这是少数情况，但要知道流程：

   1. 在你自己（有网的）电脑上装好 Ollama
   2. 执行 ollama pull qwen2.5:3b
   3. 找到模型文件，整个文件夹拷走：
      C:\Users\你的用户名\.ollama\models\
   4. 拷到客户电脑的同样位置：
      C:\Users\客户用户名\.ollama\models\
   5. 客户电脑上执行 ollama list 确认能看到

   【注意】模型文件夹可能有 5-10 GB，用 U 盘拷。
   路径里的"用户名"要换成实际的，别直接复制这条路径。


================================================================
第 5.5 部分  ④ 常用工具.bat（日常运维主力）
================================================================

这是给"部署完之后出问题"准备的。12 个功能全在一个编号菜单里，
不用记命令。客户自己也能点。

--------------------------------------------------------------
5.5.1 菜单全貌
--------------------------------------------------------------
   [1] 启动服务             启动并等到健康检查通过
   [2] 停止服务             结束占用 8085 的进程
   [3] 重启服务             停止 + 启动，一条命令
   [4] 查看运行状态         服务/端口/自启/Ollama/data 占用
   [5] 查看日志             显示最近 40 行
   [6] 打开接口文档         浏览器打开 /docs
   [7] 查看已安装模型       NEXUS 侧 + Ollama 侧都看
   [8] 下载模型             按内存推荐，也可手输
   [9] 导出诊断包           一键打包所有排障信息
   [10] 设置/取消开机自启    直接调用 ③
   [11] 修改端口             写 config.json，重启生效
   [12] 备份配置             打包 data 目录
   [13] 切换模型来源         打开悬浮窗，本地/自动/API

   【菜单顶部会实时显示】
     服务运行：是/否
     开机自启：已开启/未设置
     地址：http://127.0.0.1:8085

--------------------------------------------------------------
5.5.2 排障标准流程（重点记这个）
--------------------------------------------------------------

客户说"用不了"，按这个顺序走，不要乱猜：

  第 1 步  双击 ④，看菜单顶部
           · 服务运行=否      → 选 1 启动
           · 开机自启=未设置  → 选 10 设置
           · 两个都是是，继续往下

  第 2 步  选 4 看详细状态
           · 端口没监听       → 选 5 看日志找原因
           · Ollama 未运行    → 开始菜单打开 Ollama

  第 3 步  选 7 看模型
           · 只有兜底、没有 qwen → 选 8 下载模型
           · 有模型但客户端连不上 → 检查 /v1 结尾

  第 4 步  还不行 → 选 9 导出诊断包，发给我们

  【为什么强调顺序】
  80% 的"用不了"就是服务没起来或模型没装，
  查这两项就够了，不用一上来就要日志。

--------------------------------------------------------------
5.5.3 诊断包里有什么（选 9）
--------------------------------------------------------------
   会自动生成"诊断报告.zip"，内含：
     info.txt        系统版本/位数/内存/Python版本与位数/
                     pip版本/依赖是否装全/服务响应/端口
     nexus.log       完整运行日志
     config.json     当前配置

   【用法】让客户把这个 zip 发过来，不用他描述现象。
   这一步能省掉大量来回沟通。

--------------------------------------------------------------
5.5.4 改端口（选 11）要注意
--------------------------------------------------------------
   · 只改 config.json 的 server.port，其他配置项保留
   · 改完必须选 3 重启才生效
   · 【必须提醒客户】客户端里的接口地址要同步改，
     否则客户会以为"改坏了"
   · 开机自启不受影响（自启只是启动程序，端口由配置决定）

--------------------------------------------------------------
5.5.5 日志（重要）
--------------------------------------------------------------
   路径：<安装目录>\data\logs\nexus.log

   为什么要做这件事：
   开机自启后程序无窗口，stdout 全部丢失。
   没有日志的话，远程排障只能靠猜。

   日志特性：
     · 超过 5 MB 自动轮换为 nexus.log.1（只保留一份）
     · 记录 uvicorn 启动过程 + 每次请求（access log）
     · UTF-8 编码，用记事本可直接打开

   【注意】日志只挂在 root logger 上。
   uvicorn 的 logger 会向上冒泡，若同时给 uvicorn.error
   挂 handler，每条会写 2-3 遍，日志会虚胖。别改回去。


第 5.6 部分  ⑤ 模型切换.bat（本地 / 自动 / API 三键切换）
================================================================

--------------------------------------------------------------
5.6.1 它解决什么问题
--------------------------------------------------------------
   客户经常问两个矛盾的需求：

     "我不想联网，数据不能出门"   → 要本地
     "我这台电脑太慢，回答太蠢"   → 要 API

   以前只能改配置文件，客户不会改。
   现在做成三个按钮，点一下就行，不影响客户端配置。

--------------------------------------------------------------
5.6.2 三个按钮到底做了什么
--------------------------------------------------------------
   底层就是 config.json 里的 mode 字段：

     [本地]  → mode=offline, allow_cloud=false
               绝不允许任何非本机请求。
               net.py 在开 socket 之前就拦住。

     [自动]  → mode=auto,    allow_cloud=true
               优先本地；本地后端失败时自动转 API。
               这是唯一会"自己切换"的模式。

     [API]   → mode=online,  allow_cloud=true
               只走 API，本地模型完全不用。

   【重要】这里的"自动"不是"检测网络"。
   程序不探测网络状态，它探测的是"本地后端是否可用"。
   断网但本地模型在，就继续用本地，不受影响。

--------------------------------------------------------------
5.6.3 自动切换的触发点（代码位置）
--------------------------------------------------------------
   nexus/core/runtime.py 的 chat_message：

     本地后端抛 ConnectionError（Ollama 停了/模型卸载）
       ↓
     _try_cloud_fallback() 判断：
       · mode 是 AUTO 吗？        不是 → 放弃
       · cloud.enabled 吗？       不是 → 放弃
       · allow_cloud 吗？         不是 → 放弃
       ↓ 都满足
     改用 CloudBackend 重发同一个请求
       ↓ 成功
     返回 source="cloud"

   三条硬规则（已加测试覆盖）：
     · OFFLINE 就算 allow_cloud=true 也绝不外溢
     · 云端失败 → 退回兜底回复，不报错崩掉
     · 客户端点名要某模型，不在可用列表里就忽略

--------------------------------------------------------------
5.6.4 API 密钥怎么存（安全要点）
--------------------------------------------------------------
   密钥存在 data\cloud.key ，单独一个文件，权限 600。

   【为什么不写 config.json】
   诊断包（④ 选 9）会打包 config.json。
   密钥在里面就会被客户连文件一起发出来。

   读取优先级：
     1. 环境变量 NEXUS_CLOUD_API_KEY
     2. data\cloud.key 文件

   部署时如果客户有统一密钥，建议用环境变量，
   不要每个机器手填。

--------------------------------------------------------------
5.6.5 面板也能在浏览器里开
--------------------------------------------------------------
   地址：http://127.0.0.1:8085/panel

   和悬浮窗功能一样，多了"当前状态"和"API 设置"两块。
   客户说悬浮窗打不开时，让他用浏览器开这个地址。

--------------------------------------------------------------
5.6.6 常见问题
--------------------------------------------------------------
   点了 [API] 但回答没变？
     → 云端没配置。面板下方填地址/模型/密钥，点保存。
       或者看悬浮窗底部那行红字提示。

   点了 [自动]，本地模型没装，会怎样？
     → 直接走 API（如果配了），否则显示"未就绪"。

   客户说"我断网了还能用吗"？
     → 能，只要 [本地] 或 [自动] 且本地模型已装。
       本地推理走 127.0.0.1，不经过网卡。

   悬浮窗显示"服务未响应"？
     → 引擎没启动。用 ④ 选 1 启动，或检查端口
       （悬浮窗会自动读 config.json 里的端口）。


第 6 部分  教客户连上客户端（部署完必做）
================================================================

--------------------------------------------------------------
6.1 Cherry Studio（最常见）
--------------------------------------------------------------
   1. 打开 Cherry Studio
   2. 左下角"设置"→"模型服务"
   3. 找到"OpenAI"或点"添加提供商"
   4. 填：

      接口地址：http://127.0.0.1:8085/v1
      API 密钥：随便填，比如 123（本地服务不验证）
      模型名称：qwen2.5:7b（填客户实际装的那个）

   5. 点"检查"或"测试"，能连上就行
   6. 回到聊天界面，模型下拉框里选刚加的那个

   【最容易出错】接口地址少写 /v1
   写成 http://127.0.0.1:8085 会连不上。
   正确：http://127.0.0.1:8085/v1

--------------------------------------------------------------
6.2 Open WebUI
--------------------------------------------------------------
   如果客户用的是 Open WebUI（本地网页版），
   添加 OpenAI 兼容接口，地址同样填：
      http://127.0.0.1:8085/v1

--------------------------------------------------------------
6.3 验证真的能用（重要）
--------------------------------------------------------------
   在客户端里问一个简单问题，比如"1+1等于几"。

   ✓ 回答"1+1等于2"这类正常文字 → 成功
   ✗ 回答是固定套路（"我是 NEXUS 助手，目前..."）→ 模型没生效

   如果出现后者：
   1. 浏览器访问 http://127.0.0.1:8085/v1/models
   2. 看模型列表里有没有真实模型（qwen2.5:xxx）
   3. 没有 → 回到第 5 部分装模型
   4. 有，但客户端还是兜底 → 客户端里模型名填错了

第 7 部分  常见故障速查表
================================================================

【总原则】先双击 ④ 常用工具.bat，看菜单顶部状态。
状态正常再往下看本表；不确定就选 9 导出诊断包发过来。

现象                              原因与处理
--------------------------------------------------------------
双击 bat，窗口一闪就没了           脚本出错。右键→以管理员运行，
                                  还不行截图发技术

提示"不是内部或外部命令"           Python 没装/没进 PATH。
                                  重装 Python，勾选 Add to PATH

pip 安装卡住不动                   网络慢或被拦截。等 2 分钟，
                                  再不行退出杀毒软件重试

"端口 8085 被占用"                 用管理员权限重跑

部署成功但客户端连不上             地址漏了 /v1

客户端能连，但回答是套路文字        模型没装好。看第 5 部分

回答特别慢（超过 30 秒）           模型太大或内存不够。
                                  换小一号模型

服务用着用着停了                    那个最小化的 NEXUS Server
                                  黑窗口被关了。重新双击部署脚本

电脑重启后不能用了                  双击 ③ 开机自启.bat 重新设置
                                  （或检查杀软是否删了启动项）

开机自启不生效                      1. 双击 ③ 看提示
                                  2. 检查杀软是否拦截了启动项
                                  3. 文件夹移动过，需重跑 ③

客户说"杀毒软件报警"                误报。让客户把文件夹加白名单

nexus.pyz 打不开 / 报错            文件损坏。重新解压或重发
要关掉软件                          ④ → 选 2（或任务管理器结束 python.exe）
要重启软件                          ④ → 选 3
不知道哪里出问题                    ④ → 选 9 导出诊断包，直接发过来
想看软件到底做了什么                ④ → 选 5 查看日志
端口 8085 被别的软件占了             ④ → 选 11 改成 8086，再选 3 重启

第 9 部分  三条硬性红线
================================================================

1. 不要在客户机器上装 Chromium / weasyprint / puppeteer
   客户电脑配置普遍不高，装了会拖垮系统，也会引起投诉。

2. 不要跳过模型下载（第 4.2 步选 N）
   客户拿到一个只会说套路话的软件，一定要求退款。

3. 不要在非管理员权限下强行部署
   端口清理会失败，后面全是连锁问题，越弄越乱。
